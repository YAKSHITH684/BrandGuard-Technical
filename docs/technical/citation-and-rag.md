# Technical Specification: Citation Verification and RAG Retrieval

## 1. The Explainable Citation Contract

Black-box AI verdicts that state *"this content is non-compliant"* without citing specific rules breed creator distrust and slow down publication cycles.

BrandGuard enforces an architectural **Citation Contract**:
- Every compliance finding generated by the platform must cite an exact `source_chunk_id`.
- The frontend renders the cited source excerpt alongside the violation so creators can see the official policy rule verbatim.
- Citations returned by the LLM are cryptographically validated against the database before findings are persisted.

```
+--------------------------------------------------------------------------+
|                  RAG Candidate Context Generation                        |
|   1. Query vector retrieves chunks: [chk_sec2, chk_sec3, chk_fact1]      |
|   2. Embeds chunks into XML prompt context tags                          |
+------------------------------------+-------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
|                  Groq Structured JSON Response Generation                |
|   LLM returns findings citing: "source_chunk_id": "chk_sec2"             |
+------------------------------------+-------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
|                  Grounding & Citation Validator                          |
|   SELECT id FROM source_chunks WHERE id IN ('chk_sec2', ...)             |
|   - If chunk exists in database: Persist finding with citation           |
|   - If hallucinated chunk ID: Strip or re-assign to closest valid chunk  |
+------------------------------------+-------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
|                  UI Citation Linking (Next.js)                           |
|   FindingCard renders collapsible excerpt + 1-click link to /sources     |
+--------------------------------------------------------------------------+
```

## 2. Chunk Ingestion and Metadata Preservation

During ingestion (`backend/app/services/ingestion.py`):
1. Documents are parsed into discrete `SourceChunk` records.
2. Each chunk receives a deterministic unique identifier (e.g. `chk_guideline_sec3_p1`).
3. Attributes preserved in database:
   - `source_id`: Parent document relation (`sources.id`).
   - `section_title`: Section heading (e.g., *Section 3: Performance Claims Policy*).
   - `content`: Exact excerpt text.
   - `effective_date` & `expiry_date`: Date constraints.
   - `embedding`: 384-dimensional vector.

## 3. Grounding Verification Algorithm

In `review_pipeline.py`, after Groq returns structured findings:

```python
# 1. Collect all cited chunk IDs from findings
cited_chunk_ids = {f.source_chunk_id for f in ai_findings if f.source_chunk_id}

# 2. Query database for existence
valid_chunks = db.query(SourceChunk).filter(SourceChunk.id.in_(cited_chunk_ids)).all()
valid_chunk_map = {c.id: c for c in valid_chunks}

# 3. Validate and ground findings
for finding in ai_findings:
    if finding.source_chunk_id in valid_chunk_map:
        finding.grounded = True
        finding.source_excerpt = valid_chunk_map[finding.source_chunk_id].content
    else:
        # Prevent hallucinated citations
        finding.grounded = False
        finding.source_chunk_id = None
```

This guarantee ensures that no creator is ever presented with a hallucinated rule citation.
